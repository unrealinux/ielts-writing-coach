# 打分流程与双向校准

> **校准必须双向。** 本文件曾经只有「防虚高」清单（七条全部朝下压），实测结果是**系统性低估**：
> 在 24 篇真实考生作文上，工具的输出只覆盖 1.0 个档位，而参照覆盖 2.5 个档位；
> 回归斜率 **0.32**（无偏应接近 1.0）——低分作文被抬高、高分作文被压低，
> 全部收拢到 6.0 附近。详见 §十。
>
> 系统性低估和系统性高估**一样有害**：它让学生按错误的反馈安排复习
> （例如把本该练论证的时间花在冠词上）。

## 一、判定三问（每一项都必须走完）

对 TR/TA、CC、LR、GRA 中的每一项，独立回答：

1. **门槛**：本文最接近哪一档？该档在该项的标准是什么？（查 `band-descriptors.md`）
2. **证据**：本文哪些具体句子达到 / 未达到该门槛？引用原文。
3. **差距**：要升到上一档，缺的**那一件事**是什么？（可执行，可检验）

如果三问中第 2 问答不出具体句子，说明你没有真正读完这篇作文——回去重读，不要给分。

**第 2 问对高分和低分同样适用。** 给 5.0 要能引用 band 5 描述符里的具体特征，
给 7.0 要能引用符合 band 7 的具体句子。**"读起来很弱"和"读起来不错"都不是证据。**

## 二、防虚高清单（给分前逐条自查）

| 虚高信号 | 纠正动作 |
|---|---|
| 你给出的四项分数完全相同 | 四项独立判定；真实作文几乎不会四项齐平。必须为**每一项**分别引用判据原文，引不出就重新逐项判定。 |
| 总分 7.0+ 但没有引用任何 error-free 的复杂句 | Band 7 GRA 要求 "frequent error-free sentences"；举不出例子就降到 6.0–6.5。 |
| 因为"意思能看懂"就给了 6.5 | 6 分档本来就允许"错误但不影响理解"。能看懂是 6 的下限，不是 6.5 的理由。 |
| 因为词"看起来高级"就给了 LR 7 | 查搭配、语域、精确度。`utilize` / `a myriad of` 用错比用 `use` / `many` 更扣分（LR-WW/LR-COLL）。 |
| 因为段落分明就给了 CC 7 | 7 分要求"每段有清晰中心话题 + 逻辑推进"。只有 Firstly/Secondly/Finally 的机械分段是 6。 |
| 因为字数够就默认 TA/TR 达标 | 字数只是必要条件。Task 2 要看是否**回应全部**问题部分；Task 1 要看是否有**清晰概述**。 |
| 因为句式长就认为 GRA 强 | 长句出错（run-on、从句断裂）是 GRA 5–6 的典型特征。句子长度不换分。 |

## 三、防虚低清单（给分前同样逐条自查）

**上面七条只管一个方向。** 下面这一节是它的对称项，**必须一起走完**，否则会系统性压分。

| 虚低信号 | 纠正动作 |
|---|---|
| **四项全部落在 6.0–6.5** | 逐项问一句"**这一项有没有 7 分档证据？**"，必须**引用原文**回答。引不出反例，就不许停在 6.0。 |
| **总分正好是 6.0** | 双向各走一遍：先假设它是 **6.5**，列出支持与反对的具体证据；再假设它是 **5.5**，同样做。**取证据最强的那一个**，不要取中间值——取中间值就是把 6.0 当默认值。 |
| 作文明显强于 band 7 描述符，你却给了 6.5 | **不许以"限时条件下罕见"为由压低。** 罕见与否不是评分标准，描述符对上就给。 |
| 用"没有明显问题"作为给 6.0 的理由 | 6 分档描述符是**主动特征清单**（任务基本回应／有分段／有连接词／有简单复合句），不是"没有 7 分特征"。逐条对上才算。 |
| 给 5.0 或以下，却引不出 band 5 描述符里的具体特征 | 低分同样需要证据。"读起来很弱"不是 5 分的理由。 |
| **TR 是四项里最低的** | TR 主观性最强、最容易被系统性压低（实测偏差 −0.67，四项最大）。确认你不是因为"论证风格我不喜欢"而降它。判据只有两条：**是否回应全部问题部分**、**论点是否真的延展**。 |
| 你刚刚给过一篇 6.0，这一篇"感觉差不多" | 逐项重新对照描述符。"和上一篇差不多"是锚定，不是判据。 |
| GRA 给了 6.0，但作文里有**多个** error-free 复杂句 | 说明为什么不是 7。band 7 GRA 的原话是 "frequent error-free sentences"——够 frequent 就要认。 |

**打分前的一条反锚定要求**：开始判分时**不要预设任何档位**。
四项各自从 `band-descriptors.md` 的描述符**独立**定位，定位完之后再看它们是否齐平——
齐平是结果，不是起点。

## 四、Band 锚点参考（用于校准，不是自动给分规则）

> ⚠️ **本节不给出任何档位的出现频率，一个数字都没有，也不给某个档位贴频率标签。**
> 理由见 §十——这里曾经有过一个没有来源的频率断言，而它同时是锚定邀请。
> 档位落在哪里由**描述符的证据**决定，不由分布决定。

用于把手感拉回现实：

- **4.5–5.0**：能读懂，但结构零散、错误密集、任务只回应了一部分、字数常不足。
- **5.5**：回应了任务但论证/概述薄弱；错误频繁但基本可读；词汇局限于高频词。
- **6.0**：任务基本回应、有分段、有连接词、有简单复合句；错误可见但不阻碍理解；词汇够用但缺精确度。
- **6.5**：在 6.0 基础上，四项里有两项明显更好（通常是 CC + LR），但 GRA 或论证深度拖后腿。
- **7.0**：四项都稳定达标——立场贯穿全文、论证有延展、词汇有灵活性、复杂句多数无误。**这是"好作文"的门槛，不是"能看懂的好作文"。**
- **7.5–8.0**：需要极少错误 + 精确且自然的搭配 + 从容的衔接。
- **8.5–9.0**：母语级控制力。教学中几乎不需要讨论。

如果用户的作文明显低于其自述水平（例如自称 7 分水平但实际 6），**照实说**，并解释差在哪。这是批改的价值所在。给安慰分等于让用户在考场上损失一次机会。

**反过来同样成立**：如果作文明显高于用户自述水平，也照实说。为了"显得严格"而压分，
和给安慰分是同一个错误的两面——都让用户按错误的信息备考。

## 五、字数硬规则

| 任务 | 最低 | 后果 |
|---|---|---|
| Task 1 | 150 词 | 不足 → TA 上限 5.0 |
| Task 2 | 250 词 | 不足 → TR 上限 5.0 |

超字数不直接扣分，但会导致：检查时间不足 → GRA/LR 错误上升；Task 1 超 200 词通常意味着在罗列数据而非概述。

## 六、总分计算

```
overall = (TR_or_TA + CC + LR + GRA) / 4
```

四舍五入到最近 0.5：.25 → .5，.75 → 下一整分。

| 四项 | 均值 | 报告总分 |
|---|---|---|
| 6.5, 6.5, 6.0, 6.5 | 6.375 | **6.5** |
| 6.0, 6.5, 6.0, 6.0 | 6.125 | **6.0** |
| 7.0, 7.0, 6.5, 6.5 | 6.75 | **7.0** |
| 6.0, 6.5, 6.5, 6.5 | 6.375 | **6.5** |
| 5.5, 6.0, 6.0, 5.5 | 5.75 | **6.0** |

## 七、报告可信度要求

- 开头标注"**预估分，非官方成绩**"。
- 每项分数后紧跟一句依据（含原文引用）。
- 明确列出你在 Step 0 做的假设（例如"未提供题目，按常见 Task 2 议论文处理"）。
- 如果题目缺失，明确标注 TR/TA **未评分**，不要猜。

## 八、一处缺陷只归一个评分项（防止系统性低估）

**规则**：每一处缺陷有且只有一个**归属项**。判分时，每个评分项只统计归属它的缺陷。

**为什么要有这条**：一个逗号拼接会同时表现为"标点错误"（GRA）、"指代不清"（CC），
甚至"逻辑被掩盖"（TR）。如果三个评分项都拿它当降档证据，学生的**一个**错误被算了三次，
四项各被压低一点，总分可能少 0.5。

**这和高估一样有害，而且更隐蔽**——因为报告看起来"证据充分"、每项都有原文引用。
本 skill 自己的样例报告就犯过：同一个短语在四项里都被当作降档依据（见 §九 的实例）。

**归属优先级**（按缺陷本身的性质定，**不按它出现在哪个评分项的讨论里**）：

| 缺陷性质 | 归属项 | 其他项不得据此降档 |
|---|---|---|
| 句子边界、标点、从句结构、时态、主谓一致、冠词、单复数、语序 | **GRA** | CC 不因"标点造成的读感不顺"再降档 |
| 用词、搭配、词形、语域、拼写、重复 | **LR** | GRA 不因"用词奇怪"再降档 |
| 段落组织、中心句、连接手段、**指代**、信息推进 | **CC** | — |
| 内容：偏题、漏答、论证不足、概述缺失、数据错误、无立场 | **TR / TA** | LR / GRA 不因"内容空泛"再降档 |

**关键区分**：

- **同一句话含有多处独立缺陷 → 允许分别归属。** 例如 `It is good for the society, it can make...`
  同时有①逗号拼接（GRA）②第二个 `it` 指代不明（CC）③内容空泛无机制（TR）——三者互相独立，
  即使把标点改对、把指代写清，内容依然空泛。**这时三项各自计入是正确的。**
- **同一处缺陷被反复计入 → 禁止。** 如果 CC 的理由是"逗号让逻辑显得不清"，那和 GRA 的逗号拼接
  是**同一处缺陷**，CC 必须放弃这一条。

**判断方法**：对每一处跨项引用问一句——**"把归属项的缺陷改对之后，另一项的指控还成立吗？"**
成立 → 独立缺陷，可以分列；不成立 → 同一缺陷，只能归一处。

**报告必须声明**：凡是被两个以上评分项引用的引文，都要在 `## 缺陷归属审计` 一节里
用表格声明归属项与其他项的处理方式。`scripts/audit_report.py` 检查这一点——**未声明即不通过**。

## 九、本 skill 自己的实例（教训）

样例报告 `2026-09-13-task2.md` 中，同一个短语
`it is good for the society, it can make the country develop faster` 曾被四项同时引用：

| 报告位置 | 评分项 | 用作什么证据 | 复查结论 |
|---|---|---|---|
| 行 42 | Task Response | 论证不足（无机制） | ✅ 独立——改对标点后内容仍空泛 |
| 行 58 | Coherence & Cohesion | ~~指代不清 + 标点掩盖逻辑~~ | ⚠️ **标点那一半是重复计分**，已删除；指代不清独立保留 |
| 行 94 | Grammatical Range & Accuracy | 逗号拼接 | ✅ 主归属 |
| 错误清单第 10 行 | Lexical Resource | `LR-REG` 低语域 | ✅ 独立——语域与标点无关 |

**这是一次真实的系统性低估**：一个 20 词短语贡献了四项的降档理由。修法是删掉 CC 里那句
"标点掩盖逻辑"（换成纯粹的指代问题），并在报告里声明归属。

## 十、首次真实准确性测量（2026-09-21）

本节记录**为什么会有 §三**。改动判断规则必须有证据，这里是证据。

**方法**：24 篇真实考生 Task 2 作文（分层抽样，覆盖参照分 5.0–7.5），每篇由**一个独立代理**
按本 skill 的 Step 1–2 评分；代理只拿到题干与作文，**参照分从未进入其提示词**。

**参照**：一份公开专家标注语料的 `Overall_score` 列（四项分独立成列，四项均值按雅思取整规则
复现总分的比例为 65%、平均差 0.18）。

**结果（23 篇有效）**：

| 指标 | 值 |
|---|---|
| 参照分范围 | 5.0 – 7.5（2.5 个档位） |
| **工具分范围** | **5.5 – 6.5（1.0 个档位）** |
| 相关系数 | 0.82 |
| **回归斜率** | **0.32** |
| 平均偏差 | −0.39 |
| 平均绝对误差 | 0.61 |
| 落在 ±0.5 内 | 70% |

偏差随档位单调变化：参照 5.0 → **+0.50**；参照 7.5 → **−1.25**。

**结论**：工具把分数往 6.0 挤。这不是随机误差——随机误差不会随参照分单调变化。

**被删掉的那句话**：§四里原本写着「**6.0：最常见的"及格线"作文**」。它有两个问题——
一，bundle 里没有任何来源支持这个频率断言，写了就是编；二，它是**锚定邀请**：
把 6.0 标为"最常见"，等于每次打分前先在心里放一个 6.0，而这正是实测到的行为
（23 篇里 20 篇落在 5.5 或 6.0，11 篇总分正好 6.0）。修订后 §四 不含任何频率数字。

**已知限制**（与结论一起读）：

- 参照出处未能独立核实（同批 `train.csv` 里 78% 的评语是"Suggested Band Score"的模型腔，
  且与自己的分数列 19% 差 ≥1 档，故整个弃用）。**这测的是"与这份参照的偏差"，不是"与考官的偏差"。**
- 参照自身噪声底 0.18；每篇只评一次；全是 Task 2；代理与评分者同模型家族。
- 区间压缩这个结论**对上述限制不敏感**：它来自斜率而非均值，而参照噪声只会把斜率推向 1.0，
  不会把 1.0 变成 0.32。

### 10.1 第一次修复：**无效**（预登记的判据没有达到）

改完 §二/§三/§四 之后，用同一批 24 篇、同一套指令重跑：

| | 工具分范围 | 回归斜率 | 平均偏差 | 平均绝对误差 |
|---|---|---|---|---|
| 修复前 | 5.5–6.5 | 0.321 | −0.396 | 0.604 |
| **修复后** | 5.0–6.5 | **0.300** | −0.333 | 0.542 |
| 预设目标 | — | **≥ 0.70** | — | — |

**斜率没有回升（0.321 → 0.300）。按本节自己写下的判据，这次改动不算修复，不得作为"已修好"发布。**

平均绝对误差从 0.604 降到 0.542、低分端出现了一个 5.0——方向对，但**决定性的指标没动**。
加一份对称清单，不足以抵消整套评分指导的效应。

### 10.2 对照实验：压缩是**本文件造成的**，不是模型分辨不出来

同一批 24 篇，让 24 个独立代理**完全不读任何 skill 文件**，直接凭判断打分：

| | 工具分范围 | 回归斜率 | 平均偏差 | 平均绝对误差 |
|---|---|---|---|---|
| 参照分 | 5.0–7.5 | 1.000 | — | — |
| 用 skill（修复前） | 5.5–6.5 | 0.321 | −0.396 | 0.604 |
| 用 skill（修复后） | 5.0–6.5 | 0.300 | −0.333 | 0.542 |
| **裸模型（不读 skill）** | **4.5–7.0** | **0.550** | −0.438 | 0.604 |

**两个结论：**

1. **模型本身就会压缩**（裸斜率 0.550，低于 1.0）——"给中档分"是这个模型家族的默认倾向。
2. **本 skill 把它的区分能力又砍掉了近一半**（0.550 → 0.300）。分范围从 2.5 个档位缩到 1.5 个。

换句话说：**在绝对分数这一件事上，读了本 skill 的代理比不读的代理更不准。**
补偿性修补（再加一份清单）治不了这个——问题不在清单平不平衡，在**整套评分指导本身**。

**这条结论对 SKILL 其余部分不构成否定**：报告结构、逐句证据、错误清单、定向改写、
优先级排序的价值不受影响，本实验只测了**总分**这一项。但它意味着
**分数在一份批改报告里是可靠性最低的那一部分**，而本 skill 现在把它放在最显眼的位置
（`## 分数卡` 是报告第一节）。

**下一步要验证的方向**（按代价排序）：

1. **减去**而不是增加：把 §二/§三/§四 的清单压到最少（例如只留"每项必须引用原文"），重跑同一批，
   看斜率是否向 0.550 回升。若回升，说明指导越少越准。
2. 分开测：四项分项各自是否也压缩，还是只有总分的取整放大了压缩。
3. 若两者的斜率都上不去，就要承认**这个模型家族给不出可校准的绝对分数**，
   把报告的分数从"预估分"改成"档位排序 + 证据"，不再给绝对数字。

**限制**：n=24；每篇每条件只评一次；裸条件用了"你是一位有经验的雅思考官"的角色提示（不是纯空白对照）；
0.321 与 0.550 的差距在小样本下是**提示性**而非定论，但方向与机制一致。
