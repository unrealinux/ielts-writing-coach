# 三种失败模式与诊断优先级

批改时最常见的错误是**只看语言**。作文的失败模式有三种，互相独立，可以叠加，而且**语言越好越难察觉**。这份文件用于在写报告时快速定位"这篇真正的问题是什么"，以及给出有算术依据的提分建议。

## 一、三种模式

| 模式 | 表面特征 | 决定 | 工具信号 |
|---|---|---|---|
| **A 语法错误密集** | 结构完整、可读，但错误遍布每句；**复杂句比简单句更容易出错** | GRA·LR 的下限 | 第 5 节错误探测命中 ≥5 处 / 250 词 |
| **B 论证空洞** | 零错误、通顺、段落均衡；每个论点停在"断言 + can/may" | TR 的上限 | 第 7 节：证据 0 / 具体细节 0 / 模糊限制语 ≥6 |
| **C 跑题** | **语言与论证都很好**，但答的是相邻的另一个问题 | TR 的上限 | 第 8 节：题干覆盖 <40%、题型要求的写作动作缺失 |

> ⚠️ **上表的量化阈值是在少量样本上校准的，不是经过验证的界值。**
> 例如"以连接词开头的句子 ≥50%"来自两个样本（50% vs 26%），"题干覆盖 <40%"来自三个样本（100% / 60% / 38%）。
> 它们的作用是**触发人工复核**，不是判定结论——分析器输出里每处告警都写着"需人工确认"，请当真。
> 阈值刻意偏保守（宁可多报也不漏报）：**触发不等于一定有问题，未触发不等于一定没问题。**

**三种模式的核心判据**：

- **A**：不要数错误总数，要问"**复杂句是不是比简单句更不准确**"。是 → GRA 5.5 区间（这是 Band 5 的原始判据）；错误多但简单句干净 → 6.0 区间。
- **B**：对每个主体段的主张句问三次"为什么成立"。答不出机制 → TR 上限 6.0。特别警惕**同义反复**（"在家工作能减少通勤时间"不是论据）。
- **C**：把题干拆成**问题部分清单**，逐条在作文里找对应段落。找不到 = 漏答或偏题。**跑题无法从作文本身看出来**，必须先拿到题干。

## 二、三轴分别决定什么

| 轴 | 决定 | 三轴都干净时 |
|---|---|---|
| 相关轴（第 8 节） | TR 的**上限** | 不代表 TR 高，还要看支撑轴 |
| 支撑轴（第 7 节） | TR 的**上限** | 两个轴取低者 |
| 错误轴（第 5 节） | GRA·LR 的**下限** | 语言干净 ≠ TR 达标 |

**关键规则**：**错误轴干净、支撑轴或相关轴告警时，不要因为语言好就抬高总分。** 这是最容易发生虚高的情形。反过来也一样——相关轴和支撑轴都干净，但错误轴密集时，不要因为"内容好"就抬高 GRA。

## 三、优先级：先修最便宜的

给"下一步动作"排序时用这个顺序，并说明理由：

| 顺序 | 失败模式 | 修复动作 | 时间成本 | 收益 |
|---|---|---|---|---|
| 1 | **跑题** | 动笔前写一句"题目问的是 ___，不是 ___" | 每篇 2 分钟 | TR +1.5～2.0 |
| 2 | 机械衔接 | 删掉一半连接词，改用指代承接 | 1–2 周 | CC +0.5～1.0 |
| 3 | **空洞** | "追问三次"训练 + 情态动词清查 | 2–4 周（习惯重建） | TR +1.0～1.5 |
| 4 | 语法错误 | 冠词 / 主谓一致 / 单复数 三类专项 | 数月（系统训练） | GRA +1.0～1.5 |
| 5 | 词汇贫乏 | 话题词替换卡 + 强制限次使用 | 数月（积累） | LR +0.5～1.0 |

## 四、跨档算术（给建议时必须用）

**总分 = 四项平均，四舍五入到 0.5（.25 上进，.75 上进）。**

跨半个档位需要四项总和增加多少？**这不是一个固定值，必须每次算。**

```
增量 = 4 × (当前总分 + 0.25) − 四项总和
```

四种情况出现频率相当，取决于四项总和落在取整门槛的哪一侧（B = 当前总分）：

| 四项总和 | 当前总分 | 到下一档需要 |
|---|---|---|
| 4B + 0.5 | B | **+0.5** |
| 4B | B | **+1.0** |
| 4B − 0.5 | B | **+1.5** |
| 4B − 1.0 | B | **+2.0** |

例：总和 25.5 = 4×6.5 − 0.5 → 总分 6.5 → 需 **+1.5**；总和 24.0 = 4×6.0 → 总分 6.0 → 需 **+1.0**。

> ⚠️ **不要记成"跨档需要总和 +1.5"。** 那只是四种情况之一。
> 本 skill 的 1.3.0–1.8.0 版本曾把这个数字当规律写进文档——因为当时的三个测试样本四项总和
> 恰好都等于 4B − 0.5（是我设计分数时的巧合，不是规律）。**每次都用公式算。**
> `scripts/track_progress.py` 是按公式算的，可以直接用它的输出。

**增量决定建议该多激进：**

- **增量 ≤ 1.0**：单项提升（某一项 +1.0）就可能跨档 → 集中火力修最弱那一项
- **增量 ≥ 1.5**：单项必须显著提升（+1.5 以上），或两项各 +0.5～1.0 → 要明确"改哪几项、各改多少"

因此"单项 +0.5 毫无变化"也是错的：**当增量恰好是 0.5 时，单项 +0.5 就跨档了。**
正确的表述是"增量通常大于一次小幅提升"，而不是"小幅提升永远无效"。

**"四项都很接近"的情形**：短板不突出时，跨档往往需要同时动两项（例如 6.0/6.0/6.0/5.5，
总和 23.5 = 4×6.0 − 0.5，增量为 +1.5：单项要 +1.5，或 TR +1.0 且 GRA +0.5）。
这种作文要在报告里说清"你的问题不是某一项特别弱，而是四项都不够"，否则用户会误以为改一项就够。

## 五、五种需要主动纠正的用户误解

批改时如果察觉到用户有这些想法，在报告里直接点破：

| 用户的想法 | 事实 |
|---|---|
| 「我语法好，作文应该不错」 | 零错误 + 论证充分仍可能 TR 5.0（跑题）。语言与 TR 是两套能力 |
| 「意思都表达清楚了，应该有 6.5」 | "能看懂"是 Band 6 的**下限**。Band 6 本来就允许"错误不影响理解" |
| 「字数够了 TR 就没问题」 | 字数只是必要条件。313 词、超下限 25%，TR 仍可能 5.5 |
| 「写得多说明内容充实」 | 超长常常是跑题的副产品——多出来的篇幅花在了无关论证上 |
| 「连接词用得多 CC 就好」 | 官方标准把**机械使用**明确归入 CC 6。**以连接词开头的句子占比 ≥50% 是扣分项** |

## 六、写报告时的自查

- [ ] 我是否只看了语言，没有检查相关轴和支撑轴？
- [ ] 我给的"下一步动作"是否聚焦在一项上，而不是四项各给三条？
- [ ] 我是否**按公式算了**跨档增量（而不是套用某个固定数字）？
- [ ] 如果用户的强项和弱项差距大（如 GRA 8.0 / TR 5.0），我是否明确说了"继续打磨强项是零收益"？
- [ ] 如果四项接近（如全部 6.0 上下），我是否说明了"需要同时修两项"？
- [ ] 我是否引用了原文来支撑每一条判断？
